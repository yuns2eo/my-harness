### G5 (S5) — 전달
- 업로드 전: PNG 수 = 프레임 수, 픽셀 크기 = 정확히 3x (2x 대체 불허), 파일명 `{YYMMDD}_{작업명}_{배너종류}{_강|_고}.png` 일치(`@3x` 없음)
- 전달 후: `05/delivery.json`에 드라이브 링크 1, 노션 속성 2, Slack 댓글 ts 1, 이모지 2(`${EMOJI_START}`, `${EMOJI_DONE}`) 기록

## 2. ★1 비교 규칙
- 비교 전 정규화: 배너 쪽과 시트 쪽 모두 `\n` → 공백 1개
- 정규화 후 **바이트 동일** (공백, 문장부호 포함)
- 허용 치환 1종: `·` → `&` (rules.yaml 등록). 치환 발생 시 qa-report에 "시트 원문 / 반영값" 기록 + 승인 화면 표시
- 시트는 고치지 않는다. 그 외 불일치는 전부 FAIL

## 3. 피사체 측정 (표준편차 방식)
- 대상: 3x PNG의 밝기(grayscale) 값. 측정 결과 ÷ 3으로 Figma 좌표와 비교
- 열마다 표준편차 → **≥ 12**인 열 구간 = 피사체 가로 범위
- 행마다 표준편차 → **≥ 12**인 행 구간 = 피사체 세로 범위. 행 표준편차는 **열에서 찾은 가로 범위 안에서만** 계산한다 (넓은 띠배너에서 배경에 희석되지 않게)
- 참고: 배경 5~7, 피사체 15 이상. 흰 동물 + 밝은 배경도 잡기 위해 색 거리 대신 사용
- 측정 영역: 텍스트·로고·버튼 노드 bbox는 제외한다 (글자가 피사체로 잡히지 않게)

### S4 승인 화면

- 배너 PNG 미리보기
- Figma 프레임 링크 (프레임마다 1개, 클릭 가능한 URL)
  - 형식: `https://www.figma.com/design/${FIGMA_FILE_KEY}/?node-id={노드ID의 : → -}`
  - `fileKey`는 rules.local.yaml, 노드 ID는 `02/figma.json`에서 읽는다
  - 링크 수 = 프레임 수 (강/고 분리면 세트별로 각각). 다르면 승인 화면을 띄우지 않는다

# r3-pipeline.md
> R3 산출물. 파이프라인 5단계 / 단계별 입출력 / 되돌아가는 지점.
> 입력 변수 V1~V13과 완료 기준은 r2-scope.md, 판정 기준은 story-service.md(★1~3)를 따른다.

## 1. 단계 (story-work 순서 그대로)
| 단계 | story-work | 입력 | 출력 |
|---|---|---|---|
| **S1 요청 정리** | 1 | 스레드 URL 또는 스캔 결과 | `brief.md` (V1~V13), 요청 메시지에 `${EMOJI_START}` |
| **S2 텍스트·로고 조립** | 2 | `brief.md` | Figma 복제 섹션, 배너별 노드 ID 기록 |
| **S3 이미지** | 3+4 | `brief.md`, `input/images/` | 프롬프트 txt, 이미지가 배치된 프레임 |
| **S4 검수** | 5 | Figma 프레임 | `qa-report.md` (PASS/FAIL), 사람 승인 |
| **S5 전달** | 6+7 | 승인 기록 | PNG, 드라이브 링크, 노션 속성 2개, Slack 댓글, `${EMOJI_DONE}` |

## 2. 멈춤과 재개
| 지점 | 멈추는 조건 | 재개 조건 |
|---|---|---|
| S1 스캔 | 미확인 요청 2건 이상 | 디자이너가 1건 선택 |
| S3 이미지 대기 | V11=`Y`이고 프롬프트 txt 출력 완료 | 디자이너가 "이미지 넣었어" + `input/images/` 이미지 파일 수 ≥ 1 |
| S3 이미지 게이트 | 생성 이미지 검토 (사람) | 승인 → 배치 / 반려 → 프롬프트부터 다시 |
| S4 승인 | 스크립트 전부 PASS | 디자이너 승인 1건 |
| S5 Slack | 댓글 문구 표시 | 디자이너 확인 후 전송 |

- V11=`N` → S3 이미지 대기와 이미지 게이트를 건너뛰고 원본 이미지로 바로 배치

## 3. 되돌아가는 지점 (S4 FAIL 시)
| 실패 유형 | 복귀 |
|---|---|
| 문구 불일치(★1), 로고(★3), 폰트, 줄바꿈, `·` 사용, 레이어명 | **S2** |
| 배너 누락, 세트 수 부족(★2) | **S2** |
| 피사체 크기, 위치, 잘림, 경계선, 배경색, 얼굴이 그라데이션에 가림 | **S3 배치만** (이미지 유지) |
| 이미지 게이트 반려 | **S3 프롬프트부터** |

- 같은 복귀 지점으로 **3회** 돌아가도 PASS가 안 나오면 멈추고, 실패 항목을 보여준 뒤 디자이너 판단을 받는다

## 4. 수정 요청 (전달 후)
- **입력:** 같은 스레드 URL + "수정" + 대상 배너 종류
- **경로:** S1에서 `brief.md`를 새로 읽고 달라진 값만 표시 → **해당 배너만** S3→S4→S5. 문구가 바뀌었으면 S2부터
- **드라이브:** 파일명 유지. 순서는 다음과 같다
  1. 새 파일 업로드
  2. 업로드 성공 확인 (새 file ID 존재, 크기 > 0)
  3. 기존 파일을 **file ID로 지정해** 휴지통으로 이동
  - 2번이 실패하면 3번을 하지 않는다. **영구 삭제 금지**
- **Slack:** 새 댓글 (문구 표시 → 확인 → 전송)
- **이모지:** `${EMOJI_DONE}`가 이미 있으면 그대로 둔다

## 5. Slack 전달 문구 (고정, 이것만)
| 경우 | 문구 |
|---|---|
| 최초 전달 | `<@요청자> 전달드립니다!` + 드라이브 링크 |
| 수정 전달 | `<@요청자> 수정해두었습니다!` + 드라이브 링크 |

- `요청자` = 요청 메시지 작성자의 Slack user ID

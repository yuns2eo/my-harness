## 1. 한다 / 하지 않는다
| 한다 | 하지 않는다 |
|---|---|
| 트리거 해석, `state.json`으로 다음 단계 결정 | Figma 쓰기 |
| 서브에이전트 호출 (넘기는 입력은 **run id + 단계**만) | 외부 쓰기 (Slack, 노션, 드라이브, 이모지) |
| 게이트 스크립트 실행, 결과에 따라 진행 또는 복귀 | PASS/FAIL 판단 (스크립트 결과만 따름) |
| 사람 확인·승인 받기, `approval.json`·`state.json` 기록 | run 폴더 안 01~05 파일 편집 |

## 2. 게이트는 뒤집을 수 없다
- 단계 전진 조건 = 게이트 스크립트 **exit code 0** 하나뿐
- "거의 맞으니 통과" 없음. 예외가 필요하면 디자이너가 rules.yaml을 고친다
- `state.json` 단계 상태 5종: `pending | running | waiting_human | pass | fail`

## 3. CLAUDE.md 범위
- 넣는 것: 라우팅표(트리거 → 단계 → 에이전트), 금지사항, 문서 포인터
- **판정 수치 0개**. 값은 쓰지 않고 rules.yaml 키만 가리킨다
- 길이 **150줄 이하**
- R8에서 "CLAUDE.md 안 rules.yaml 수치 0건" 검사

## 4. 외부 장애와 동시성
### 재시도 = 상태 확인 먼저
MCP 호출(Slack, 노션, Figma, 드라이브)이 실패하면 **실제 상태를 먼저 확인**한다. 확인 없이 재시도 금지.

| 대상 | 재시도 전 확인 | 이미 반영됐으면 |
|---|---|---|
| Slack 댓글 | 스레드를 다시 읽어 내 댓글(같은 문구) 존재 여부 | 재전송 안 함, `delivery.json`에 ts 기록 |
| 드라이브 업로드 | 월 폴더 검색: 파일명 일치 + md5 일치 | 재업로드 안 함, file ID 기록 |
| 노션 속성 | 페이지를 다시 읽어 두 속성 값 비교 | 재기록 안 함 |
| 이모지 | 메시지 reaction 목록 확인 | 다시 달지 않음 |

- 확인 결과 미반영이면 재시도 1회(`retry.external`). 그래도 실패하면 멈추고 보고
- 중간 실패 시 성공한 것만 `delivery.json`에 기록 → "이어서 해줘"로 나머지만 실행 (r4-artifacts.md §4)
- 드라이브: 파일명만 같고 md5가 다르면 "이미 있음"이 아니다 (수정 경로의 기존 파일일 수 있음, r3-pipeline.md §4)

### Slack 멘션 검증
- 전송 직후 스레드를 다시 읽어 방금 댓글의 원문(raw text)에 사용자 멘션 토큰 `<@U…>`(`|이름` 포함 형태 허용)이 있는지 확인
- 토큰 없이 `@이름` 텍스트로 들어갔으면 알림이 안 간 것 → **FAIL로 보고** (자동 재전송 금지, 디자이너 판단)

### 동시성
- 진행 중 run은 **1개**만. 새 요청이 오면 "진행 중 run 있음: {id}"라고 알리고 멈춘다

# story-work.md
> 작업 도메인 (R0-B). 주어가 "나(디자이너)"인 문장만 쓴다.
> AI 없이 손으로 하던 순서 그대로. 🚦 = 멈칫한 지점(게이트 자리), ➡️ = 다른 사람에게 넘기는 지점(에이전트 경계).

## 작업 흐름 7문장
1. 디자이너가 Slack 디자인 채널에서 아직 확인 표시가 없는 브랜드전 요청을 찾고, 노션 기획안과 구글시트에서 문구, 혜택, 브랜드, 강/고 구분을 확인한다
2. 디자이너가 Figma 배너 파일에서 배너 템플릿 섹션을 통째로 복제하고, 3종 배너에 텍스트와 브랜드 로고를 넣는다
3. 디자이너가 상품 원본 이미지를 받고 ChatGPT로 배너용 이미지를 만든다 🚦 "이 이미지 써도 되나"
4. 디자이너가 이미지를 3종 배너에 각각 넣고 피사체 크기, 위치, 경계선, 배경색을 맞춘다
5. 디자이너가 줄바꿈, 여백, 정렬을 보고 "이 정도면 넘겨도 되나" 하고 멈칫한다 🚦
6. 디자이너가 PNG 3배수로 뽑아 구글 드라이브 기획안 월 폴더에 올린다
7. 디자이너가 요청 스레드에 드라이브 링크를 한 줄로 달고, 노션 디자인 경로와 진행 상황을 바꾼다 ➡️ 기획자

## 산출물 (명사)
| 단계 | 남는 것 |
|---|---|
| 1 | 요청 정리 `brief.md` (문구, 혜택, 브랜드, 규격, 강/고, 기획안 월) |
| 2 | Figma 복제 섹션 + 3종 프레임 (텍스트, 로고 반영) |
| 3 | 생성 이미지 원본 파일 + 사용한 프롬프트 txt |
| 4 | 이미지가 들어간 3종 프레임 |
| 5 | 검수 결과 `qa-report.md` |
| 6 | PNG 3x 파일 (메인 1125×600, 띠 3375×666, 리뉴얼 981×981) |
| 7 | Slack 스레드 댓글, 노션 속성 2개 |

## 🚦 멈칫 지점 (게이트 자리)
| 위치 | 멈칫하는 이유 | 누가 판정 |
|---|---|---|
| 3번 뒤 | 생성 이미지의 제품 라벨, 포장이 원본과 같은지, 구도가 배너에 맞는지 | 사람 |
| 5번 뒤 | 줄바꿈, 여백, 제품 크기, 얼굴이 그라데이션에 가리는지 | 스크립트 + 사람 최종 확인 |

## ➡️ 넘기는 지점 (에이전트 경계)
| 위치 | 누구에게 |
|---|---|
| 3번 | ChatGPT (이미지 생성 도구) |
| 7번 | 기획자 (요청자) |

## 되돌아가는 지점
- 5번 검수에서 걸리면 → 4번(이미지 배치) 또는 2번(텍스트)으로
- 3번 이미지가 반려되면 → 3번 다시 생성
- 전달 후 수정 요청이 오면 → 해당 배너만 4~7번 다시, 파일명은 유지

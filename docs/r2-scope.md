# r2-scope.md
> R2 산출물. 무엇이 매번 달라지나 / 하네스 사용자 / 완료 기준.
> 판정 기준은 story-service.md(★1~3), 작업 순서는 story-work.md. 이 문서는 둘을 연결하는 범위만 정한다.

## 1. 요청마다 달라지는 값 (입력 변수)
이 목록 밖의 값(템플릿, 규격, 폰트, 색, 좌표, 자간 등)은 전부 고정값이다. 하네스가 바꾸면 위반.

| # | 변수 | 형태 | 출처 |
|---|---|---|---|
| V1 | 브랜드명 | 문자열 1~N개, 복수면 `A&B&C` | 노션/시트 |
| V2 | 메인 문구 | 문자열 (시트와 글자까지 동일, ★1) | 시트 |
| V3 | 서브 문구 | 문자열 (★1) | 시트 |
| V4 | 혜택 | 문자열 (★1) | 시트 |
| V5 | 할인율 | 정수 % (★1) | 시트 |
| V6 | 강/고 분리 | `none` \| `dog+cat` → 세트 수 1 \| 2 (★2) | 노션 |
| V7 | 요청 배너 종류 | {메인, 띠, 리뉴얼}의 부분집합, 기본 3종 (★2) | 노션 |
| V8 | 기획안 월 | `YYYY-MM` → 드라이브 폴더 | 노션 |
| V9 | 작업명 / 제작일 | 작업명 문자열, `YYMMDD` | 노션 / 실행일 |
| V10 | 상품 원본 이미지 | 파일 1~N개 | 요청 스레드/노션 |
| V11 | GPT 이미지 필요 여부 | `Y` \| `N` | 노션 |
| V12 | 로고 파일 | 파일. **logo variant에 없는 신규 브랜드일 때만** | 요청 스레드/노션 |
| V13 | 기타 요청사항 | 자유 텍스트 (노션 원문 그대로 보존) | 노션 |

- V11=`N` → 원본 이미지를 그대로 사용, 이미지 생성 단계와 이미지 게이트 생략
- V12 존재 → 받은 로고 파일로 신규 logo variant 등록(사람 승인) 후, ★3을 variant 일치로 판정
- V13 → 스크립트 판정 대상 아님. 사람 승인 때 체크리스트로 함께 표시

## 2. 하네스 사용자
| 역할 | 누구 |
|---|---|
| 실행 | 디자이너 본인 1명 |
| 승인 | 디자이너 본인 1명 |
| 결과 수신 | 기획자 (하네스 미사용, 스레드 링크만 받음) |

## 3. 시작 입력
1. 스레드 URL이 주어지면 → 그 스레드를 사용 (최우선)
2. 없으면 → 채널 2곳 자동 스캔
   - 우선: `${CHANNEL_PRIMARY}`
   - 보조: `${CHANNEL_SECONDARY}`
   - 대상: 확인 이모지 3종(`${EMOJI_START}`, `${EMOJI_DONE}`, `:white_check_mark:`) 중 **하나도 없는** 브랜드전 요청
   - 선택: 미확인 요청이 **1건이면 바로 진행**, **2건 이상이면 목록을 보여주고 디자이너가 고른다** (자동 선택 금지)
   - 1회 실행 = 1건
3. 이미지: 하네스는 프롬프트 txt만 생성. 디자이너가 생성 이미지를 `input/images/`에 원본 바이트 그대로 넣는다

## 4. 완료 기준 (한 문장)
> 요청 1건에 대해 **PNG 개수 = V7 개수 × 세트 수(1|2)** 이고, 모든 PNG가 명명규칙과 3x 규격을 지키고, **★1·★2·★3 판정이 전부 PASS**이고, **사람 승인 기록이 1건** 있으면 완료다.

### 외부 작업
| 시점 | 작업 | 방식 | 완료 확인 |
|---|---|---|---|
| 작업 시작 | 요청 메시지에 `${EMOJI_START}` | 자동 | 이모지 존재 |
| 승인 뒤 | 드라이브 월 폴더 업로드 | 자동 | 업로드 링크 1개 존재 |
| 승인 뒤 | 노션 속성 2개(디자인 경로, 진행 상황) | 자동 | 두 속성 값 갱신됨 |
| 승인 뒤 | Slack 스레드 댓글 | **문구 먼저 표시 → 디자이너 확인 → 전송** | 댓글 1개 존재 |
| Slack 전달 후 | 요청 메시지에 `${EMOJI_DONE}` | 자동 | 이모지 존재 |
